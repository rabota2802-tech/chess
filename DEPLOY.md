# Локальная приёмка и публикация

## Локальная приёмка

Запустите `node server/main.js` (Node.js 24 LTS) и откройте http://127.0.0.1:8787/chess/. По умолчанию слушается только loopback. У каждой браузерной сессии свой профиль. Для двух игроков используйте обычное и приватное окно, создайте комнату в первом и откройте приглашение во втором.

Альтернатива — `docker compose up --build -d`. Контейнер запускается от пользователя node, порт привязан к localhost, а каталог /data смонтирован как постоянный том. `GET /health` возвращает JSON. `docker compose down` останавливает сервис с сохранением тома. Для резервного копирования комнат остановите процесс перед копированием SQLite вместе с файлами WAL или используйте SQLite Backup API.

## Сервер для удалённых игроков

Нужны Node.js 24 LTS или Docker, постоянный диск для SQLite, сетевой адрес с HTTPS и обратный прокси. Одна реплика сервера обслуживает комнаты; запись и проверка ревизии выполняются последовательно в одном процессе. Состояние запрашивается примерно раз в 0,9 секунды. Выбран короткий HTTP-опрос, чтобы восстановление после потери связи и работа через обычный HTTPS-прокси не требовали настройки отдельного транспорта. Денежные расходы зависят от выбранного размещения; лицензий на движок, сервисов аналитики и платных API для работы не требуется.

Для production задайте `CHESS_ORIGINS=https://rabota2802-tech.github.io` для Compose или `ORIGINS` для процесса Node. При прямом запуске укажите `CHESS_DB` на постоянном диске. Прокси должен сохранять Authorization и исключать секреты из журналов. Сервер ограничивает запросы участника по подтверждённому месту в комнате (180 в минуту). Создание и вход имеют общий защитный лимит по адресу TCP-соединения, создание ограничено 60 запросами в минуту. Заголовки X-Forwarded-For не участвуют в идентификации. Ссылки содержат приглашение во фрагменте URL. На GitHub Pages адрес API задан в клиенте; локальный клиент обращается к своему origin. Приватные ответы используют no-store.

## Публикация 1.1

Владелец разрешил production-релиз. Текущий статус фиксируется в RELEASE-AUDIT.md. Публикация клиента следует за фактической проверкой HTTPS API. Публичный тестовый хостинг в этом релизе не используется.

1. Проверить существующий VPS и прокси, выполнить развёртывание по VPS-PLAN.md. Через публичный HTTPS проверить /health, Origin, две игровые сессии, ход, часы и восстановление связи. Сверить состояние остальных сервисов.
2. Выполнить `node scripts/cache.js`, проверить Git diff, контрольные суммы Stockfish и тесты из TEST-REPORT.md. Сверить manifest с базовой версией. По адресу /chess/ должны быть доступны JS, WASM, GPL и соответствующие исходники.
3. Перевести PR №1 из Draft в Ready, проверить точный SHA перед слиянием. Дождаться успешной публикации Pages для этого коммита, сравнить выданные index.html и sw.js с артефактами main. Повторить игровые сценарии с действующего адреса. Только затем считать 1.1 опубликованной.

## Приглашение

Выберите «Играть онлайн», цвет и контроль времени, нажмите «Создать комнату». Передайте ссылку из поля «Ссылка для друга» одному сопернику. Он открывает её в обычном браузере и нажимает «Войти по приглашению». Для возвращения в текущую комнату используйте тот же браузер и «Вернуться в комнату».

## Обновление установленного приложения

До проверки новой версии сохраните текущую партию и не очищайте данные сайта. На iPhone откройте приложение с экрана «Домой» при наличии сети. Дайте ему загрузить файлы, закройте все окна этого приложения, затем откройте снова. На MacBook закройте также вкладки старой версии. После появления меню проверьте «Продолжить партию», сохраните копию через «Настройки», дождитесь статуса «Готово к офлайн-игре», отключите сеть и повторите запуск. Штатное обновление использует прежнюю установку. Сетевой сбой при загрузке новой версии оставляет активным предыдущий исправный кэш.
