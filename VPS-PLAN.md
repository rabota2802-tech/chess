# План пилота на Джино

Владелец разрешил размещение. В панели Джино подтверждён включённый Ubuntu VPS с 2 CPU, 4 ГБ RAM и диском 50 ГБ, из которых свободно 39,8 ГБ. Размещение и расписание ниже ещё не применены. Доступ в ОС нужен для сверки контейнеров, прокси и портов.

## Ресурсы и границы

Движок Stockfish, нейросеть и анализ работают на устройстве игрока. Сервер обслуживает комнаты по HTTP, проверяет ход и часы, сохраняет состояние в SQLite/WAL. Браузер опрашивает сервер примерно раз в 0,9 с, то есть около 2,2 запросов в секунду на активную комнату. Для действующего протокола нужен HTTPS. При дальнейшем переходе на WebSocket понадобится WSS и поддержка Upgrade в том же отдельном виртуальном хосте; клиент 1.1 работает по HTTPS.

Один локальный замер во время функциональных испытаний: контейнер 28,81 МиБ RAM, CPU 5,40% по docker stats, 11 процессов/потоков, /data 116 КиБ. Размер образа ARM64 — около 255 МБ. Это точка измерения, а не оценка предельной нагрузки. Начальный бюджет на VPS — 0,5 CPU и 256 МиБ RAM на контейнер; запланировать минимум 1 ГиБ свободного диска для образов и журналов, отдельно место под активную БД, WAL, снимки и запас для роста. Для обновления одновременно нужны старый и новый образы. Перед изменениями сверить идентичность узла, свободное место, Docker и Compose, контейнеры, порт и конфигурацию прокси. Записать исходное состояние сервисов и сделать копию затрагиваемых конфигурационных файлов. По последнему заданию нагрузочные испытания исключены.

## Изолированное развёртывание

1. Выделить для Chess отдельный каталог, поддомен, незанятый loopback-порт, проект Compose (например chess-online) и его собственный том rooms. Не подключать каталоги/сети чужих приложений или Docker-сокет внутрь контейнера. Использовать зафиксированный и проверенный SHA ветки или релиза; сохранить digest предыдущего образа.
2. Установить CHESS_PORT на выделенный порт, CHESS_ORIGINS — список точных HTTPS-origin клиентов. Контейнер запускается от пользователя node с read-only корнем, без Linux capabilities и права повышения привилегий. По умолчанию заданы 0,50 CPU, 256 МиБ RAM, 64 PID, ограниченные журналы и restart unless-stopped. SQLite — один записывающий экземпляр на отдельном томе.
3. Подготовить отдельный виртуальный хост с HTTPS и обратным проксированием только к порту Chess. Запретить кэш ответов API, передавать Authorization, исключить учётные данные из журналов. Проверить конфигурацию прокси до применения. Публичный порт Node не открывать. Опрос ограничивается после проверки игрока, отдельно для каждого места. Сетевые заголовки клиента не используются для определения личности.
4. Проверить GET /health через HTTPS, затем создать тестовую комнату из двух разных сетей, сыграть, отключить одну сеть, вернуться, проверить часы и реванш. Healthcheck только сообщает состояние; restart unless-stopped перезапускает завершившийся процесс, но не лечит зависание. Подключить внешний монитор HTTPS и оповещения о нескольких последовательных сбоях. Отслеживать 429/5xx, задержку запросов, RAM/CPU, рестарты/OOM, свободное место и возраст последней копии.

## Копирование и восстановление

Для этой конфигурации хранить выпуски в /opt/chess-online/releases/<git-sha>, ссылку current направлять на проверенный выпуск. В /opt/chess-online/.env записать CHESS_PORT и CHESS_ORIGINS. Файл окружения нужен также для служебных команд. Применить Compose с именем chess-online. Записать SHA и ID образа перед обновлением.

После проверки образа выполнить от root `/opt/chess-online/current/ops/chess-maintenance backup` и затем `/opt/chess-online/current/ops/chess-maintenance check`. Проверить наличие cron, flock, curl и python3; установить ops/chess-online.cron как /etc/cron.d/chess-online (root:root, 0644). Ежедневный запуск в 03:17 по времени сервера создаёт снимок через VACUUM INTO, проверяет integrity_check и оставляет семь последних успешных дневных снимков. Каталог /opt/chess-online/backups доступен root, файлы имеют режим 0600. Эти копии находятся на том же VPS. Внешнее резервирование не настроено. Каждые пять минут проверяются HTTPS, локальный ответ сервера с чтением таблицы rooms и возраст копии. Ошибки видны в `journalctl -t chess-online`. Канал удалённых уведомлений не подключён.

Проверять восстановление в **новом** томе и в отдельном контейнере с новым loopback-портом. Использовать копию в качестве /data/chess.sqlite, назначить права сервисному пользователю. Новая комната и восстановление известной тестовой комнаты после перезапуска проверяют разные вещи — нужны оба сценария. Исходный том не заменять во время тренировки. Если VPS был выключен, игровые часы продолжают отсчёт по реальным меткам.

## Обновление, откат, удаление

Перед обновлением проверить копию, собрать новый образ отдельно, прогнать приёмку на копии данных. Остановить только контейнер Chess, заменить его на проверенный образ и подключить существующий том. При несовместимой схеме заранее подготовить план миграции и обратной совместимости. При отказе вернуть предыдущий digest; восстановление снимка требует отдельного решения, так как отбрасывает более поздние ходы.

Для отключения остановить только проект chess-online и убрать только выделенный маршрут прокси, монитор и расписание резервирования Chess. Команда `docker compose -p chess-online down` сохраняет том. После передачи финальной копии и отдельного решения о сроке хранения можно удалить строго перечисленные том, образы, DNS-запись и сертификат Chess. Общие сети, образы других проектов и глобальную очистку Docker не использовать.
